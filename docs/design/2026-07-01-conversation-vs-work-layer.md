## 계기
LLM/Convex 비용 최적화(nano 전환·캐던스·쿨다운·Convex 쿼터 초과)를 따라오다 근본 질문에 도달:
**"아바타끼리 LLM으로 대화시키는 게 InKoEx에서 무슨 의미인가?"**

## 핵심 통찰
- **AI Town:** 아바타 간 대화 = **상품 그 자체** (소셜라이제이션 실험이 존재 이유).
- **InKoEx:** 그 대화는 상품이 아니라 **유휴/전시 레이어**. 진짜 가치는 **"작업 레이어"** — 실제 일하는 에이전트 팀 + 그 일을 클릭하면 산출물로 역추적(06-27 문서의 그 구분).
- 즉 **AI Town이 공짜로 주는 건 유휴 레이어뿐**이고, InKoEx의 가치인 **작업 레이어는 아직 미개척**. (며칠간 다듬은 아바타·iso·UI·대화비용은 전부 유휴/전시 레이어였음.)

## "대화"의 두 가지 의미 (혼동 금지)
1. **분위기용 잡담 (AI Town식)** — "셋은 일하고 둘은 논다"의 '노는' 모습. 코히런스·깊이 불필요. 그냥 살아 보이면 됨. → **캔드로 충분.**
2. **진짜 작업 협업** — 전략가가 구현자에게 지시하듯, 실제 일의 일부인 통신. 의미 있고 역추적 가능. → **실제 에이전트 채널(cmux/API)에서 일어남. AI Town엔 없음.**

## 결정: 3층 구조
| 레이어 | 무엇 | 비용 |
|---|---|---|
| **작업(가치)** | 실제 에이전트가 실제 채널로 통신·작업. 화면은 그 **실제 사건을 시각화**(재생성 아님, 역추적 O) | 실제 작업 비용(정당) |
| **유휴(전시)** | 캔드 활동·상태 신호·움직임·템플릿 말풍선 | **~$0** |
| ~~아바타 LLM 잡담~~ | AI Town의 코어였던 것 | InKoEx엔 **대체로 불필요** (걷어내거나 최소화) |

## 캔드/템플릿 행동 스펙트럼 (비용 순)
| 단계 | 방식 | API |
|---|---|---|
| ① 순수 캔드 | 미리 쓴 행동/대사 풀 + 규칙 선택 | 0 |
| ② 템플릿+메타데이터 | `"{이름} {장소}로 이동 중"`, 슬롯을 소요시간 등 실데이터로 | 0 |
| ③ 캔드 + 가끔 LLM | 대부분 캔드, 아주 가끔만 새 대사 한 줄 | 극소 |
| ④ 완전 LLM 대화 (현재) | 매 메시지 LLM 호출 | 비쌈 |

**핵심:** AI Town의 `convex/constants.ts:ACTIVITIES`(책 읽기·공상·정원)가 이미 ①. 비싼 건 그 위에 얹은 **LLM 대화 레이어(`agentGenerateMessage` 경로)뿐.** 그 레이어만 최소화하면 됨.

## 왜 이 방향인가
- **정직함 경계(06-27 2.3):** 싼 모델이 실제 작업 내용을 흉내 내면 그건 "가짜 정보" → 유일한 해자(진짜 라이브성)가 무너짐. 그래서 잡담은 작업을 반영하면 안 되고, 반영 안 할 거면 굳이 LLM일 이유도 없음.
- **비용:** 잡담을 LLM화 + 작업까지 대화시키면 데이터·API가 기하급수, 게다가 코어 작업과 연동도 안 됨.
- **전시 효과는 움직임+활동+상태 신호로 충분히 남.**

## 비용 함의 (이 결정이 비용 실타래를 매듭짓는다)
- 잡담 캔드화 → **유휴 레이어 API ~$0.** 남는 LLM 비용 = 실제 작업(정당) + (선택) 가끔 잡담 한 줄.
- 대화 물량 자체가 사라지므로 **Convex 사용량·LLM 비용 문제도 근본적으로 축소** (지금 겪는 쿼터·API비용의 상당 부분이 이 잡담 레이어에서 나옴).
- 즉 "저가 모델·로컬 이전"보다 **더 근본적인 레버 = 애초에 그 대화를 안 하는 것.**
